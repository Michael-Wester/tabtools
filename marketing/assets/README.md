# Final store screenshot source artwork

This directory preserves the final editable, five-image promotional artwork for
all **29 registry locales**, plus the separate **global English design**. It is
independent of generated store-listing text and is not regenerated by the locale
catalogue scripts. It does not publish or change a live store listing.

Every set uses this order:

1. Overview
2. Sort by site
3. Right-click cleanup
4. Cleanup count
5. Inactive tabs

The footers read `01 / 05` through `05 / 05`. The right-click page intentionally
retains the original stylized Canva illustration. These are promotional interface
illustrations, **not native Chrome screenshots**. Sample tab counts are illustrative.

## What is preserved

- `sources/<locale>.html`: the actual final authored HTML, including approved
  translated wording, fitted line breaks, RTL geometry and page order. Only
  repeated embedded data URIs were replaced by relative shared-asset references.
  `global.html` preserves the distinct original English artwork.
- `shared/`: six Inter font weights, 29 SVG inputs and one small Instagram PNG
  input. Each repeated asset is stored once. These are artwork inputs, not
  generated store-sized PNG exports.
- `manifest.json`: SHA-256 fingerprints for every shared asset, deduplicated HTML,
  original self-contained HTML, individual page, and the 150 approved PNG exports.
  All paths are portable and repository-relative or relative to an export folder.
- `materialize.js`: dependency-free Node tool that verifies fingerprints and
  restores the exact original self-contained HTML bytes.
- `render.py` and `requirements-render.txt`: repeatable HTML → PDF → opaque RGB
  PNG workflow, with five 1280 × 800 images per set.
- `licenses/Inter-OFL.txt`: the supplied OFL text, with the copyright notice
  aligned to the embedded fonts’ own 2016 metadata.

The 30 self-contained originals total 89,040,275 bytes. Shared storage reduces the
preserved source material to approximately 5.3 MB. No full-page PNG/PDF exports or
historical intermediate reconstruction scripts are committed here.

The historical HTML section IDs are preserved too. In localized sources the
right-click section is still named `05-Right-Click`; its actual DOM position,
manifest order, output filename and printed footer are all **3**. Do not sort
pages by these historical section IDs.

## Verify and restore the final sources

Use the repository's Node toolchain; no browser, Python packages or network access
is needed for source verification:

```sh
node marketing/assets/materialize.js verify
node --test tests/store-assets.test.js
node marketing/assets/materialize.js materialize /tmp/tabtools-artwork en fr global
```

Omit locale arguments to materialize all 30 sets. Each output is
`<output>/<locale>/TabTools.html`. Re-inlining every shared asset reproduces each
preserved original byte-for-byte, not merely equivalent DOM or visible wording.
Sources can also be opened directly from this checkout to edit their text and
positions, with `shared/` alongside them. The renderer uses the original embedded
asset form to eliminate relative-path differences.

Intentional source or asset edits require a review and explicit fingerprint
updates in `manifest.json`; old approved-export hashes must not be silently
relabelled as outputs of new artwork. The source checks reject accidental drift.
For a local draft preview before updating source fingerprints, Node callers may
use `inlineSource(source, { verify: false })`; shared assets remain hash-checked.

## Render PNGs

Required tools:

- Node, Python 3.12, a Python virtual environment, and the pinned requirements
- Poppler's `pdftoppm`, Fontconfig's `fc-match`, and WeasyPrint's native runtime
  libraries (including Pango and HarfBuzz)
- Installed **Noto Sans Hebrew Regular/Bold** and **Noto Sans CJK Regular/Bold**,
  including JP, KR, SC and TC families, for Hebrew and CJK sources

Inter is embedded and does not need system installation. Noto fonts and native
libraries are intentionally not bundled. On Debian/Ubuntu the relevant font and
utility packages include `fonts-noto-core`, `fonts-noto-cjk`, `fontconfig` and
`poppler-utils`; install the native dependencies required by your platform's
WeasyPrint package as well.

```sh
python3 -m venv marketing/assets/.venv
marketing/assets/.venv/bin/python -m pip install -r marketing/assets/requirements-render.txt
marketing/assets/.venv/bin/python marketing/assets/render.py /tmp/tabtools-artwork en he ja global
```

On Windows, use the virtual environment's `Scripts/python.exe` and put the native
executables/libraries on `PATH`. This workflow was verified on Linux; Windows and
macOS rendering have not been tested. Omit locales to render all sets.

Outputs include self-contained HTML, a five-page PDF, `screenshot-1.png` through
`screenshot-5.png`, and `render-report.json` with tool versions and comparisons to
the approved PNG fingerprints. The script stops for unknown locales, missing
fonts, changed inputs, an unexpected page count, or an incorrect PNG format.
Generated outputs belong outside the repository (or under ignored `rendered/`).

### Determinism and original-export limits

Source restoration is byte-exact on any supported Node platform. Rendering uses
fixed dimensions, explicit page order and pinned Python dependencies, but raster
output also depends on system fonts, native library versions and Poppler.
PDF metadata can vary. Do not promise cross-platform pixel identity solely from
Python dependency pins; inspect the output and its hash report before upload.

The final localized PNGs used WeasyPrint plus Poppler. The first two slots were
retained from the earlier approved exports; slots 3–5 were reordered and given
matching five-image footers. Their actual final hashes are recorded here.

The final **global PNGs** were produced differently: only the footer region
`(1120, 735)–(1230, 778)` was replaced on original approved PNG pixels. Re-rendering
`global.html` produces the editable design, but does **not** reproduce those exact
composited PNG pixels. Those raster originals are not included in this source-only
archive. The manifest retains the approved final hashes for checking separately
retained release exports, and the render report explicitly reports mismatches.
The rendering command does not patch or pretend to reproduce those originals.

A verification render on the recorded Linux runtime reproduced **144 of 145**
localized PNGs byte-for-byte. Hungarian right-click differed in 232 menu-text
pixels despite a byte-exact HTML roundtrip; the wording and layout were visually
unchanged in the inspected region. Its approved-export hash remains intact.
See `verification.json` for exact comparison evidence and font/runtime versions.
